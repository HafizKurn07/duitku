# Duitku

This project reconstructs a repeatable build from the deployed files that were available. The original application source and source maps were not present.

## Build

Requires Node.js 20 or newer. Install the development tools before running the format or full check commands:

```powershell
npm ci
npm run check
```

`npm run check` checks formatting, runs the tests, builds the site, and verifies the output. To format the JavaScript sources after editing, run `npm run format`. The build alone still has no runtime dependencies and can be run with `node scripts/build.mjs`; verify it with `node scripts/verify-build.mjs`.

The generated deployable site is written to `dist/`. Deploy the **contents** of that directory to a static host configured to serve `index.html` and `sw.js` from the same application root.

## Deploy to Vercel

Import `HafizKurn07/duitku` in Vercel. The included `vercel.json` configures the project to install dependencies with `npm ci`, build with `npm run build`, and serve the generated `dist/` directory. No environment variables are required.

The generated site is a static client-side app. Its routes use URL fragments, so no server-side route rewrite is needed. The browser stores finance data in local storage; it is not uploaded by the app.

## Project layout

- `src/` is the editable source of truth.
- `dist/` is generated by the build and is the only current deployment output.
- `legacy-deploy/` preserves the older root-level deployment that was present before the source reconstruction. It is archived for reference and is not used by the build.
- `scripts/` contains the build and output verification commands.

Do not edit files in `dist/` or `legacy-deploy/`; make changes in `src/` and rebuild. The copies of vendor libraries, fonts, and icons under `src/` and `dist/` are intentional: source contains inputs, while the static deployment needs its own self-contained assets.

## Recovered files

- `src/index.html` is the recovered application markup.
- `src/assets/app.css` and `src/assets/app.js` are the CSS and JavaScript bundles copied from the deployed app. The JavaScript bundle is formatted for readability, but its generated identifiers and original bundled structure remain because the modular source code was not available.
- `src/assets/finance.js` contains the readable monthly/yearly summaries, category breakdown, daily/weekly chart data, top expenses, transaction changes, target savings, and wallet balance calculations used by the app. The build checks that the application bundle delegates to these tested functions.
- `src/assets/wallets.js` defines only the three general wallet types—cash, bank, and e-wallet—and normalizes existing wallet records without changing their balances.
- Transfers between wallets are recorded separately from income and spending. Optional transfer fees reduce the source wallet and appear as expenses in reports.
- Net target contributions reduce the monthly budget remaining and the safe-per-day amount; target withdrawals offset that reduction.
- Target deposits are reported as expenses and withdrawals as income in daily, weekly, monthly, and yearly reports; target names appear in category breakdowns. These movements are reporting-only and do not create duplicate wallet transactions.
- Reports provide daily and weekly date-filtered summaries, along with the existing monthly and yearly views.
- `src/assets/backup.js` provides readable backup JSON export, backup file validation, and download handling. Excel workbook mapping remains in the recovered app bundle because it depends on the original app's data model.
- `src/tests/backup.test.mjs` covers JSON export/import, malformed and oversized files, format dispatch, and skipped rows.
- `src/tests/financial.test.mjs` covers monthly/yearly and date-range totals, net and savings rates, category percentages, target contributions, wallet balances, transfers and fees, graph aggregation, and transaction create/edit/delete behavior.
- `src/tests/wallets.test.mjs` covers the three general wallet types and legacy wallet-type inference.
- `src/assets/vendor/`, `src/assets/fonts/`, and `src/icons/` contain the app's deployed assets.
- `src/sw.js` is the service worker template. The build generates its cache version and precache list.
- `THIRD-PARTY-NOTICES.md` and `licenses/` retain notices and license texts for bundled third-party software and fonts.

The application source bundle contains the wiring to the finance, backup, and wallet modules. The build itself only copies source files, hashes asset filenames, rewrites the HTML asset references, excludes tests from deploy output, and generates the service worker cache metadata. It no longer searches or rewrites application code.
